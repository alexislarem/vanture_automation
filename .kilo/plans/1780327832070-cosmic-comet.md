# Plan: n8n Workflow Architecture for "Automation Created"

## Objective
Design and deliver a production-ready n8n workflow for the `fexessencial.com` platform that triggers when a new automation is created. The workflow will validate the payload, register a metric in Supabase, notify the user via Gmail, notify the internal team via Slack, and include robust error handling.

## Workflow Architecture (High Level)
1.  **Trigger**: Webhook (`/automation-created`) with header-based authentication.
2.  **Validation**: JavaScript Code node to ensure payload integrity and enrich the object with a `is_free_plan` flag.
3.  **Metric Logging**: HTTP Request node to Supabase (PostgREST API).
4.  **Customer Communication**: Gmail node with dynamic HTML content (conditional CTA for free users).
5.  **Internal Ops Notification**: Slack node for real-time monitoring.
6.  **Global Error Handling**: Error Trigger node connected to a dedicated Slack alert channel.

## Implementation Steps

### 1. Detailed Node Configuration Design
- **Webhook**: Define path, method, and security header (`x-fexessencial-secret`).
- **Code Node**: Implement JS logic for field presence check and plan flag assignment.
- **HTTP Request (Supabase)**: Configure headers (apikey, Authorization, Content-Type, Prefer) and JSON body.
- **Gmail**: Design the HTML template with conditional logic for the Pro upgrade CTA.
- **Slack (Success)**: Construct the structured message for the `#automations` channel.
- **Error Trigger**: Map error details (`execution.lastNodeExecuted`, `error.message`) to a Slack alert.

### 2. Credential & Environment Variable Mapping
- **n8n Credentials required**:
    - `Supabase Service Key` (for HTTP Request).
    - `Gmail OAuth2` (for Gmail node).
    - `Slack OAuth2` (for Slack node).
- **Environment Variables required**:
    - `WEBHOOK_SECRET`
    - `SUPABASE_URL`
    - `SUPABASE_SERVICE_KEY`

### 3. Output Generation
- Construct the complete n8n JSON structure.
- Draft the node-by-node architectural explanation.
- Compile the environment variable list with placeholders.
- Write the `curl` command for local testing.

## Deliverables
1.  Full n8n JSON.
2.  Architectural explanation.
3.  Environment variables list.
4.  Test `curl` command.

## Constraints & Compliance
- No UI nodes.
- No mock data in production nodes.
- All responses in Spanish as requested by the user.
- Technical instructions/logic in English.
